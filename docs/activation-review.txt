Verified friction and fixes

H1 partially held. Draft persistence and atomic onboarding already existed;
there is no evidence of a general refresh-reset bug. However, the original
description overrode corrected names/locations at
b5f405b:app/src/routes/Onboard.tsx:499. Activation now prefers reviewed
values, including after a reload. Null/malformed draft shapes no longer
crash onboarding, early manual-save failures produce an error toast, and
step navigation respects reduced motion. Existing storage keys are reused.

H2 held as a guidance gap. Setup placed its continue action after Telegram
and an unavailable mobile-app card. Home's milestones ordered knowledge,
connections, then work; its stage also depended on selected/seeded channels
(app/src/hooks/useBusiness.ts:87). Setup now starts with a first-task CTA;
Telegram is an optional disclosure that opens for unfinished pairing. Home
shows a durable first-task invitation before connection guidance. Chat
offers three private draft tasks in EN/BM. Website imports do not dismiss
the invitation (app/src/lib/business.ts:208); pending/failed activity loads
do not falsely declare a new account. The inbox screen explains the next
steps after signup. No scheduled completion reminder was added.

H3 did not hold as a functional prerequisite. The existing finish handler
already allowed web chat without Telegram, and the worker setup endpoint
does not require a connector. The UI implied otherwise: its progress
counted Telegram as one of three steps at
b5f405b:app/src/routes/Setup.tsx:115. Progress now measures profile/runtime
preparation only, so optional Telegram does not leave it at 67%.

H4 held. b5f405b:app/src/routes/SignIn.tsx:103 claimed email delivery on HTTP
failures and even network exceptions. It now reports network/server/IP
rate-limit failures, retains the address, and offers resend/change-email.
Expired-link copy no longer claims a replacement was sent. Neutral 204
responses remain neutral to preserve account-existence protection.
b5f405b:app/src/lib/repo/gate.tsx:70 silently selected demo mode after a
failed session check. It now distinguishes confirmed 401 from service
failure and offers retry, with a 15-second session-check timeout. Strict
Mode reuses each startup attempt to avoid duplicate migration.

An additional mismatch: worker/src/routes/runs.ts:406 rejects work while
the runtime is preparing. The old setup copy promised an inline fallback.
The copy now explains that the owner may need to retry in chat. Backend
readiness and execution rules are unchanged.
